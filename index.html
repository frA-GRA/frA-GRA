Background

What is OMS?

Open Mission Systems (OMS) is an open standard for mission-critical avionics middleware. Its Critical Abstraction Layer (CAL) decouples software components through a typed, publish/subscribe message bus — enabling safe, composable architectures for unmanned and manned vehicles.

Critical Abstraction Layer (CAL)

Defines the interface between flight software components and the Abstract Service Bus. Messages are generated from UCI XML schemas; the CAL handles serialization, QoS, topic lifecycle, and UUID identity. This org implements CAL per OMSC-SPC-001 Rev L in Rust.

Abstract Service Bus (ASB)

The underlying publish/subscribe transport (e.g. DDS, UDP). The CAL abstracts ASB details so components are bus-agnostic. Applications write to topics; the CAL and ASB handle delivery to any subscriber on the same bus.

UCI Schema Types

Unified Communications Interface (UCI) defines all message schemas as XML Schema (XSD). Types cover entities, ownship, sensors, commands, and status. The CAL generates typed Rust structs from these schemas at build time.

Service Identifiers & UUIDs

Every OMS service is identified by a UUID v1/v3/v4 (RFC 4122). The CAL binds one instance per (Service ID, ASB ID) pair, ensuring exactly one active writer per topic within a service boundary.

Repositories

Projects

Three repositories, each a self-contained piece of the OMS ecosystem.

rcal

OMS Critical Abstraction Layer implemented in Rust. Satisfies all 55 CERT CAL requirements from OMSC-SPC-001 Rev L. Provides typed UCI message generation, topic lifecycle management, QoS, and UUID identity.

View on GitHub

rcal-ardupilot

MAVLink-to-UCI gateway for ArduPilot SITL. Receives MAVLink telemetry from a simulated (or real) ArduPilot vehicle and publishes it as OMS UCI messages on the CAL bus.

View on GitHub

cosmos-oms

OpenC3/COSMOS plugin that translates OMS UCI messages into COSMOS telemetry and commands. Enables ground station operators to monitor OMS-based vehicles through the COSMOS interface.

View on GitHub

Getting Started

Running an Example System

The hub repo includes a Docker Compose file that wires ArduPilot SITL, the rcal-ardupilot gateway, and cosmos-oms into a complete system.

Clone the hub and run:

git clone --recurse-submodules \
  https://github.com/frA-GRA/frA-GRA

cd frA-GRA
docker compose \
  -f docker/docker-compose.yml up

Requires Docker 24+ with Compose V2. Container images are placeholders — see individual repos for build instructions.

Data flow:

ArduPilot SITL
Simulated copter vehicle
rcal-ardupilot
MAVLink → UCI translation
OMS Bus (ASB)
UCI typed messages
cosmos-oms
OMS → COSMOS telemetry
OpenC3/COSMOS
Ground station UI
